# v1.6.3 Pre-Push Bug Hunt

Post-tag, pre-push review of everything between `v1.6.2` and `v1.6.3` (~50
commits: transcription network-awareness, clips banner, quote-strip + artwork
migrations, async migration system, upgrade smoke test, bridge server).

Method: primary line-by-line review, then two independent agents — one
adversarially verifying each candidate claim, one hunting the same diff with
no knowledge of the candidate list. Findings below are the merged, verified
result. Each verified bug got a **failing jest test first**, then a fix, plus
an analysis of why the suite missed it (see "Tests and fixes" at the end).

## Findings

### F1 — Debug dumps committed into release history (HIGH, release blocker)

Commit `b2ba7e4` ("db: unify migrations as async...") added to the repo root:
`adb_bugreport.txt`, `adb_logcat_crash.txt`, `adb_shell_dumpsys_dropbox.txt`,
`adb_shell_dumpsys_exitinfo.txt`, and `dumpstate-2026-09-02-12-35-17.zip`
(38MB full device bugreport). All five are in the `v1.6.3` tag and current
master.

- Impact: `git push origin master v1.6.3` publishes device logs/identifiers
  and permanently bloats the repo.
- Nothing is pushed yet. Fix requires **history rewrite + re-tag** (user
  decision; release artifacts don't embed the commit hash, so re-tagging a
  rewritten but content-identical tree doesn't invalidate them).
- Why tests missed it: no repo-hygiene check anywhere; `prepare` preflight
  checks for a *dirty* tree, not for tracked junk.
- New test: `bin/__tests__/hygiene.test.ts` — fails while the files are tracked.

### F2 — Swallowed migration failure runs a silent, degraded session (MEDIUM)

`initialize_application.ts` catches a `runMigrations()` throw, logs to
console, and dismisses the splash. The trade (crash-loop → degraded session)
is intentional; two consequences are not:

1. **No user-visible signal.** Settings/hydration are skipped; store keeps
   `DEFAULT_SETTINGS`. If the user touches any Settings toggle in that
   session, `setSettings` writes all four columns from defaults — e.g. a real
   `sync_enabled=1` silently clobbered to 0.
2. **Migration 0 is not idempotent** (latent, exposed by the swallow).
   It records itself in `status` *before* creating the rest of the schema. A
   partial failure leaves `migration=0`; every later launch resumes at
   migration 1 against missing tables and now fails *silently*, forever.
   v1.6.2 at least crashed loudly.

Refuted parts of the original claim: the library is not empty after a
mid-range migration failure (screens re-fetch on focus), and migration 13's
per-row native failures are caught internally. Also verified safe: nothing
touches the DB before `migrate()` (v1.6.2's store-creation reads were
correctly removed).

- Why tests missed it: init tests only assert `initialized === true` on
  failure — the "never a permanent splash" half of the contract, never the
  "never silent" half. Migration tests replay prefixes but never rerun a
  *partially-failed* migration; the idempotency rule itself had no test.
- New tests:
  - `initialize_application.test.ts` › *surfaces a migration failure to the
    user* — expects a `toast` dep call (surfacing mechanism is a proposal;
    the `toast()` helper already exists and fits the one-line fix).
  - `migrations.test.ts` › *recovers when migration 0 failed after recording
    itself*.

### F3 — Metered-gate awaits outside try/catch strand 'starting' (LOW-MED)

`start_transcription.ts:38-39`: `whisper.isModelDownloaded()` and
`network.fetch()` run before the try/catch. A rejection (RNFS/NetInfo edge)
leaves `status: 'starting'` forever — Settings shows "Starting...", no
banner, no retry path — and the rejection escapes to `onNetworkChange`, which
calls the action without `.catch`.

- Why tests missed it: failure tests all inject failure through
  `transcription.start()`; the gate's own awaits (new in v1.6.3) got
  happy-path tests only.
- New tests: `start_transcription.test.ts` › *lands on error when the
  model-presence check itself fails* / *...network check itself fails*.

### F4 — waiting-wifi wedge race (LOW)

Sequence: `waiting-wifi` → Wi-Fi appears (auto-start fires) → user taps
"Download now" → Wi-Fi drops before the auto call's `network.fetch()`
resolves. The auto call writes `waiting-wifi` back while the manual
(`ignoreMetered`) download is past the gate. Every subsequent 'downloading'
progress emit and the final `'on'` transition are gated on
`starting|downloading` and get dropped: UI shows "Waiting for Wi-Fi" through
the entire 465MB download while the queue is actually on. Self-heals on the
next unmetered network event.

- Why tests missed it: action tests are single-invocation; no test interleaves
  two concurrent `startTranscription` calls (the gate writes state without
  knowing another call is past it).
- New test: `start_transcription.test.ts` › *a manual download-now start ends
  on despite a concurrent metered check*.

### F5 — Migration 12 has no upgrade hook (LOW, process rule)

MIGRATIONS.md: every data-transforming migration gets a hook in
`bin/upgrade_hooks.ts`. Migration 12 (quote strip) transforms data; only 13
has a hook. The v1.6.2→v1.6.3 upgrade run exercised 12 with no assertions
beyond "no crash + index". Jest covers the transform, so impact is low.

- Why tests missed it: hook coverage lived only in a prose rule.
- New test: `bin/__tests__/upgrade_hooks.test.ts` — hand-maintained list of
  data-transforming migrations (currently `[12, 13]`), fails for 12. Also
  guards `LATEST_MIGRATION === migrations.length - 1` (passes today).

### F6 — Shipped-and-already-fixed: prepare died between commit and tag

v1.6.3's `cmdPrepare` cached `apkPath('maestro')` *after* the release build's
`prebuild --clean` wiped `android/` — `copyFileSync` threw after the
`release: vX.Y.Z` commit, before tagging. Fixed on master by `c68bd56`
(stash before the wipe); both agents confirmed the fix sound. No test: the
pipeline is a monolithic function; unit tests cover only its pure helpers.
Making steps testable is a possible future refactor, not done here.

## Verified non-bugs (adversarially checked, held up)

- **Pre-migration DB access**: none. Constructors assign fields only; store
  initial state uses constants; event listeners can't fire pre-init; root
  layout gates rendering on `initialized`.
- **Transcription state machine** (beyond F3/F4): stop-mid-download,
  final-attempt failure, retry/backoff ordering, network flaps during the
  retry wait — all safe; whisper's `idle` emit is synchronous in `finally`
  before the rejection propagates, so ordering is deterministic.
- **WAL concern in toolkit DB pulls**: expo-sqlite v16 sets no journal-mode
  pragma; SQLite default is DELETE, so `cat` of the main file sees all
  committed data. Residual: a live-app pull can be torn mid-transaction
  (magic-bytes check only) — read-only tooling flake, tolerated where it
  matters. Would become real if expo-sqlite ever defaults to WAL; a
  `PRAGMA journal_mode` assert in `doctor` would future-proof it.
- **Migration 12 double-ellipsis** (`"text..."` + suffix → `text......`):
  matches what the new pipeline produces for the same input — convergent by
  design, idempotent. The short-clip variant (`"Hello"...` stripped where the
  live pipeline wouldn't) is real but cosmetic, per-device, and the existing
  migration test deliberately encodes strip-regardless-of-duration.
- **Library tap during another book's load** (silent no-op + navigation to
  the other book): confirmed but byte-identical to v1.6.2 behavior — not a
  regression. Same for the 25ms duration poll's missing timeout.
- **Native `encodeArtwork`**: sample-size math, exact-cap scaling, recycle
  paths all correct. Migrations 12/13 idempotency, memory rules, and sync
  semantics (per-device vs converging) all match the docs.

## Smaller notes (no tests)

- `metadata.ts` docstring says callers should treat a null downscale as
  "skip, not clear"; migration 13 deliberately clears. The docstring is the
  wrong half — fix the comment.
- `withBridge` kills the `npx` wrapper; if the signal isn't forwarded, an
  orphaned tsx server holds the port and a *later* run's health check can
  pass against a stale bridge bound to the wrong `--device`.
- Bridge `check/artwork-cap` on a not-yet-rooted emulator triggers the first
  `adb root` (adbd restart) mid-flow — potential connection flake in
  standalone `test --e2e`.
- `play()` failure after the library's navigate is console-only (was an
  Alert pre-v1.6.3).
